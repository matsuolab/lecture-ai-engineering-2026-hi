# लेक्चर 06 का अभ्यास और होमवर्क — एजेंट से MCP सर्वर के टूल इस्तेमाल करें

## इस लेक्चर के लक्ष्य

- लेक्चर 03 के शब्दावली टूल वाले अपने MCP सर्वर को एजेंट से इस्तेमाल करें।
- मॉडल को भेजे गए टूल के नाम, विवरण और आर्ग्युमेंट दिखाएँ और पढ़ें।
- दूसरे प्रदाताओं के MCP सर्वर को सेटिंग फ़ाइल में जोड़कर इस्तेमाल करें।

अपने fork पर GitHub Codespaces में अभ्यास करें। लेक्चर 01 में दर्ज की गई Gemini API कुंजी इस्तेमाल करें।

## MCP सर्वर इस्तेमाल करने के तीन तरीके

इन तीन तरीकों को इसी क्रम में आज़माएँ।

| | अपना सर्वर शुरू करें | प्रकाशित सर्वर इस्तेमाल करें | दूर चल रहे सर्वर से जुड़ें |
|---|---|---|---|
| कनेक्शन | एजेंट आपके एनवायरनमेंट में कमांड से सर्वर शुरू करता है | `uvx` सर्वर डाउनलोड करके आपके एनवायरनमेंट में शुरू करता है | एजेंट पहले से चल रहे सर्वर से जुड़ता है |
| अभ्यास | STEP 1 और STEP 2 (शब्दावली सर्वर) | STEP 3 (fetch सर्वर) | STEP 4 (AWS Knowledge सर्वर) |
| सेटिंग | `"command": "uv"` | `"command": "uvx"` | `"url": "https://…"` |

अपने एनवायरनमेंट में सर्वर शुरू करने के लिए `command` दें। दूर चल रहे सर्वर से जुड़ने के लिए `url` दें।

### तैयारी — lec06 ब्रांच बनाएँ (लगभग 2 मिनट)

1. GitHub पर अपने fork के पेज में अपडेट उपलब्ध हो तो **Sync fork → Update branch** चुनें।
2. Codespaces के टर्मिनल में ये कमांड क्रम से चलाएँ।

```bash
git switch main
git pull --no-rebase
git switch -c lec06
uv sync --frozen
```

3. `ls app/mcp_agent.py` चलाएँ और देखें कि फ़ाइल का नाम दिखाई देता है।

- पिछली ब्रांच में बदलाव बचे होने से `git switch main` रुक जाए, तो अपना काम commit करें और फिर चलाएँ।
- `a branch named 'lec06' already exists` दिखे, तो `git switch lec06` से उस ब्रांच पर जाएँ।
- `git pull --no-rebase` में `CONFLICT` दिखे, तो अपने बदलाव बचाने के लिए `git merge --abort` चलाएँ। फिर नीचे के निर्देश अपनाएँ।

#### पिछले लेक्चर का काम अधूरा हो तो

पाठ्यक्रम की रिपॉज़िटरी के मौजूदा लेक्चर 06 वाले कोड से शुरू करें। ये कमांड क्रम से चलाएँ।

```bash
git fetch https://github.com/matsuolab/lecture-ai-engineering-2026-hi.git main
git switch -c lec06 FETCH_HEAD
uv sync --frozen
```

Sync fork में टकराव दिखे तो भी यही तरीका अपनाएँ। अपने commit बचाने के लिए **Discard commits** न चुनें।

### STEP 1 — अपने सर्वर के टूल की सूची देखें (लगभग 4 मिनट)

देखें कि एजेंट शब्दावली सर्वर शुरू करता है और उसके टूल मॉडल को देता है।

```bash
uv run python -m app.agent --list-tools
uv run python -m app.mcp_agent --list-tools
```

दोनों कमांड API कुंजी के बिना चलती हैं।

1. पहली कमांड लेक्चर 05 तक इस्तेमाल किए गए एजेंट के टूल दिखाती है। इनमें `search_materials` शामिल है।
2. दूसरी कमांड की पहली पंक्ति बताती है कि एजेंट ने शब्दावली सर्वर कैसे शुरू किया। उसके नीचे सर्वर से मिले टूल दिखते हैं।
3. सूचियों की तुलना करें। नाम, विवरण और आर्ग्युमेंट दोनों में मॉडल तक एक ही रूप में पहुँचते हैं।

दूसरी कमांड का आउटपुट ऐसा होगा।

```text
[server] glossary: कमांड से शुरू (uv run python -m app.mcp_server)
मॉडल को दिखने वाले टूल: 1

[glossary_search_glossary]
  पाठ्यक्रम की शब्दावली में शब्द खोजें और उसकी परिभाषा तथा संबंधित Lecture लौटाएँ।

  AI इंजीनियरिंग या इस पाठ्यक्रम (AIE2026) से जुड़े किसी विशेष शब्द का
  उत्तर देने से पहले इसे इस्तेमाल करें। query में केवल एक खोज शब्द दें (जैसे "LoRA")।
  आर्ग्युमेंट: {"query": {"title": "Query", "type": "string"}}
```

MCP टूल के नाम में पहले सर्वर का नाम, फिर अंडरस्कोर, फिर टूल का नाम आता है। `glossary_search_glossary` में `glossary` सेटिंग में दिया सर्वर है और `search_glossary` `app/tools.py` का फ़ंक्शन है। उपसर्ग से अलग-अलग सर्वरों में एक ही नाम वाले टूल पहचाने जाते हैं।

### STEP 2 — एजेंट से सवाल पूछें और टूल कॉल देखें (लगभग 4 मिनट)

देखें कि सवाल का उत्तर देने में एजेंट MCP सर्वर का टूल कॉल करता है।

```bash
uv run python -m app.mcp_agent --trace "AIE2026 पाठ्यक्रम में होमवर्क के 3 स्तर कौन से हैं?"
```

यह वही सवाल है जो लेक्चर 03 में पूछा था। `--- trace ---` के नीचे ये पंक्तियाँ देखें।

1. `[tool call]` में `glossary_search_glossary` और मॉडल के चुने आर्ग्युमेंट दिखते हैं।
2. `[tool return]` में MCP सर्वर से लौटी शब्दावली की सामग्री दिखती है।
3. `[usage]` में मॉडल के कम से कम दो जवाब दिखते हैं। मॉडल पहले टूल कॉल करता है और अगले जवाब में उसका परिणाम पढ़कर उत्तर देता है।

लेक्चर 03 में एजेंट फ़ंक्शन को सीधे कॉल करता था। यहाँ MCP सर्वर फ़ंक्शन को कॉल करके परिणाम एजेंट को लौटाता है।

### STEP 3 — प्रकाशित सर्वर डाउनलोड करें और इस्तेमाल करें (लगभग 5 मिनट)

वेब पेज लाने वाले fetch सर्वर को सेटिंग में जोड़ें और जाँचें कि एजेंट उसे इस्तेमाल कर सकता है।

1. `app/mcp_servers.json` खोलें। `glossary` के बंद होने वाले ब्रैकेट के बाद कॉमा लगाएँ और `"fetch"` की चार पंक्तियाँ जोड़ें।

```json
{
  "mcpServers": {
    "glossary": {
      "command": "uv",
      "args": ["run", "python", "-m", "app.mcp_server"]
    },
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch==2026.11.11", "--no-readability-js"]
    }
  }
}
```

2. पहली कमांड चलाएँ। `[server] fetch: कमांड से शुरू` और सूची में `fetch_fetch` देखें।
3. दूसरी कमांड से सवाल पूछें। `[tool call]` की पंक्ति में `fetch_fetch` और URL देखें।

```bash
uv run python -m app.mcp_agent --list-tools
uv run python -m app.mcp_agent --trace "https://modelcontextprotocol.io/ की शुरुआत का हिंदी में तीन पंक्तियों में सार दें।"
```

- `uvx` प्रकाशित प्रोग्राम डाउनलोड करके चलाता है। fetch सर्वर आपके Codespace में चलता है। पहली कमांड पहली बार चलने पर लगभग 10 सेकंड लेती है।
- `==2026.11.11` वर्ज़न तय करता है। बाहरी सर्वर के अपडेट उसका व्यवहार बदल सकते हैं।
- `--no-readability-js` से सर्वर पेज की सामग्री निकालने के लिए सिर्फ़ Python इस्तेमाल करता है।
- `fetch_fetch` का विवरण मॉडल को अंग्रेज़ी में उसी रूप में मिलता है जैसा सर्वर के लेखक ने लिखा है।

### STEP 4 — दूर चल रहे सर्वर से जुड़ें (लगभग 5 मिनट)

URL के ज़रिए AWS के MCP सर्वर से जुड़ें और जाँचें कि एजेंट उसे इस्तेमाल कर सकता है।

1. `app/mcp_servers.json` खोलें। `fetch` के बंद होने वाले ब्रैकेट के बाद कॉमा लगाएँ और `"aws"` की एक पंक्ति जोड़ें।

```json
{
  "mcpServers": {
    "glossary": {
      "command": "uv",
      "args": ["run", "python", "-m", "app.mcp_server"]
    },
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch==2026.11.11", "--no-readability-js"]
    },
    "aws": {"url": "https://knowledge-mcp.global.api.aws"}
  }
}
```

2. पहली कमांड चलाएँ। `[server] aws: URL से कनेक्शन` देखें और जाँचें कि `aws_` से शुरू होने वाले टूल जुड़ गए हैं।
3. दूसरी कमांड से सवाल पूछें। `[tool call]` में `aws_` से शुरू होने वाला टूल देखें।

```bash
uv run python -m app.mcp_agent --list-tools
uv run python -m app.mcp_agent --trace "AWS दस्तावेज़ खोजें और Amazon S3 में वर्ज़निंग दो पंक्तियों में समझाएँ।"
```

पहली कमांड की शुरुआत इन तीन पंक्तियों से होगी।

```text
[server] glossary: कमांड से शुरू (uv run python -m app.mcp_server)
[server] fetch: कमांड से शुरू (uvx mcp-server-fetch==2026.11.11 --no-readability-js)
[server] aws: URL से कनेक्शन (https://knowledge-mcp.global.api.aws)
```

AWS का सर्वर पहले से चल रहा है। एजेंट सीधे उसके URL से जुड़ता है और सवाल AWS को भेजा जाता है।

### बाहरी टूल जोड़ने से पहले क्या जाँचें

STEP 3 और STEP 4 में आपने सेटिंग में कुछ पंक्तियाँ जोड़कर दूसरे प्रदाताओं के सर्वर इस्तेमाल किए। सर्वर जोड़ने से पहले दो बातें जाँचें।

1. **सर्वर का प्रदाता कौन है?** पता करें कि सर्वर कौन देता है और उसका सोर्स कोड कहाँ है। fetch MCP रिपॉज़िटरी से और AWS Knowledge AWS से मिलता है। ऐसे सर्वर जोड़ें जिनके स्रोत की पुष्टि कर सकें।
2. **कौन-से जोखिम बताए गए हैं?** README या आधिकारिक पेज के नोट और डिफ़ॉल्ट व्यवहार पढ़ें। fetch का README अंदरूनी IP पते तक पहुँच से होने वाले सुरक्षा जोखिम बताता है। दूर चल रहे सर्वर के टूल को दिया गया डेटा उसके प्रदाता के पास जाता है।

fetch की डिफ़ॉल्ट सेटिंग अंदरूनी संसाधनों की रक्षा करती है और अपने-आप पेज लाने के बारे में साइट के नियम मानती है।

| डिफ़ॉल्ट व्यवहार | विकल्प |
|---|---|
| `localhost` और अंदरूनी नेटवर्क जैसे निजी पते छोड़ देता है | `--allow-private-ips` से उन तक पहुँच मिलती है |
| जिन पेजों को लाने की मनाही साइट की `robots.txt` में है, उन्हें छोड़ देता है | `--ignore-robots-txt` से उन पेजों तक पहुँच मिलती है |
| बाकी पेज किसी भी होस्ट से लाता है | `--allowed-hosts` से होस्ट सीमित कर सकते हैं |

MCP रिपॉज़िटरी के सर्वरों सहित किसी भी सर्वर को जोड़ने से पहले उसका प्रदाता और बताए गए जोखिम जाँचें।

### STEP 5 — काम जमा करें और Codespaces रोकें (लगभग 3 मिनट)

`answer.md` में परिणाम लिखें, PR बनाएँ और Codespace रोकें।

1. `lectures/06/answer.md` खोलें। STEP 1 का टूल नाम और STEP 2 से STEP 4 की `[tool call]` पंक्तियाँ चिपकाएँ। नाम और आर्ग्युमेंट वैसे ही रखें जैसे दिखे।
2. बदलाव commit और push करें।

```bash

git push -u origin lec06
```

3. GitHub पर अपने fork में `lec06` से `main` के लिए PR बनाएँ। जाँचें कि base repository आपका fork है।
4. नीचे बाईं ओर **Codespaces** चुनें और फिर **Stop Current Codespace** चुनें।

`answer.md` में लिखने का उदाहरण।

```text
- STEP 1 में टूल का नाम — glossary_search_glossary
```

STEP 4 पूरा न हुआ हो तो जितना काम हुआ है उतना जमा करें। बाकी काम बाद में उसी ब्रांच पर push करें।

| URL देने पर fetch कॉल नहीं होता | `app/mcp_agent.py` में `INSTRUCTIONS` में एक पंक्ति जोड़ें जो दिए गए URL को fetch से पढ़ने के लिए कहे |
| `aws` जोड़ने के बाद कनेक्शन नहीं बनता | URL जाँचें। अनुरोधों की सीमा भी हो सकती है। लगभग एक मिनट रुककर फिर कोशिश करें |
| अनुरोधों की सीमा पूरी हो गई | लगभग एक मिनट रुकें और वही कमांड चलाएँ |
| `GEMINI_API_KEY` नहीं मिली | लेक्चर 01 के अनुसार Codespaces secret दर्ज करें और Codespaces दोबारा शुरू करें |

| उन्नत | Claude Code, Codex या Gemini CLI जैसे अपने किसी सॉफ़्टवेयर के आधिकारिक दस्तावेज़ में MCP सर्वर की सेटिंग देखें। पसंद न हो तो VS Code चुनें। उसकी सेटिंग की तुलना `app/mcp_servers.json` से करें |

### बुनियादी होमवर्क

| हिस्सा | फ़ाइल |
|---|---|
| सर्वर | `app/mcp_server.py` बदलें। यही फ़ाइल तय करती है कि कौन-से टूल उपलब्ध हैं |
| एजेंट | `app/mcp_servers.json` और `app/mcp_agent.py` को वैसे ही रखें |

1. `app/mcp_server.py` खोलें। उदाहरण की आख़िरी पंक्ति `TODO` टिप्पणी के नीचे डालकर फ़ाइल सहेजें।

   ```python
   server.tool()(tools.search_glossary)

   # TODO(बुनियादी होमवर्क): get_lecture_summary भी उपलब्ध कराएँ
   server.tool()(tools.get_lecture_summary)
   ```

2. `git status` चलाएँ। STEP 5 में अभ्यास का काम commit हो चुका है, इसलिए केवल `app/mcp_server.py` बदली हुई दिखनी चाहिए।
3. जाँचें कि `glossary_get_lecture_summary` टूल सूची में दिखता है।
4. पूछें कि लेक्चर 02 में क्या सीखेंगे और देखें कि नया टूल कॉल होता है।
5. `uv run pytest -q` चलाएँ और सभी टेस्ट पास होने की पुष्टि करें।

```bash
git status
uv run python -m app.mcp_agent --list-tools
uv run python -m app.mcp_agent --trace "लेक्चर 02 में हम क्या सीखेंगे?"
uv run pytest -q
```

हर बार शुरू होने पर एजेंट सर्वर से उपलब्ध टूल की सूची माँगता है। इस तरह वह आपके जोड़े हुए टूल को पाता है।

### कार्यान्वयन वाला होमवर्क

1. लेक्चर 03 का `make_quiz` `app/mcp_server.py` में बुनियादी होमवर्क की तरह उपलब्ध कराएँ। नया टूल बनाना हो तो उसी फ़ाइल में फ़ंक्शन लिखें और उसके ठीक ऊपर `@server.tool()` लगाएँ।
2. आर्ग्युमेंट सीमा के बाहर हो, जैसे ऐसा लेक्चर नंबर जो मौजूद नहीं है, तो `return` से साफ़ संदेश लौटाएँ।
3. ऐसा सवाल पूछें जिसमें आर्ग्युमेंट सीमा से बाहर जाए और `--trace` में परिणाम देखें।

```bash
uv run python -m app.mcp_agent --trace "लेक्चर 99 के लिए एक क्विज़ बनाएँ।"
```

- `return` से लौटाया संदेश `[tool return]` में दिखता है और मॉडल तक जाता है।
- `raise` से आई त्रुटि `[tool error]` में दिखती है। तुलना करें कि मॉडल को दोनों स्थितियों में क्या मिलता है।

### उन्नत होमवर्क

1. Claude Code, Codex या Gemini CLI जैसा कोई सॉफ़्टवेयर चुनें जिसका आप इस्तेमाल करते हैं। अपनी पसंद न हो तो VS Code चुनें। इस काम के लिए दस्तावेज़ पढ़ना काफ़ी है।
2. आधिकारिक दस्तावेज़ में देखें कि उसमें MCP सर्वर कैसे सेट किया जाता है।
3. इस तरीके की तुलना `app/mcp_servers.json` से करें और अंतर लिखें।

| सवाल | क्या देखें |
|---|---|
| सेटिंग कहाँ लिखते हैं? | फ़ाइल का नाम और जगह, या सर्वर दर्ज करने की कमांड |
| कमांड से सर्वर कैसे शुरू होगा? | `"command"` के बराबर वाली सेटिंग |
| URL से कैसे जुड़ेंगे? | `"url"` के बराबर वाली सेटिंग |
| सेटिंग कहाँ लागू होती है? | एक प्रोजेक्ट में या सभी प्रोजेक्ट में |

दस्तावेज़ देखने की तारीख और उसका आधिकारिक URL लिखें। सेटिंग का तरीका बदल सकता है।
