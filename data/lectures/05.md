# Lecture 05: बाहरी टूल और MCP

## इस Lecture के उद्देश्य

- एजेंट के टूल को ऐप के भीतर के फ़ंक्शन से अलग "बाहरी सेवा" बनाने की अवधारणा समझें।
- MCP (Model Context Protocol) से टूल किसी भी संगत क्लाइंट के साथ साझा करके देखें।

## मुख्य बिंदु

1. **बाहरी टूल**: वेब पृष्ठ लेना, फ़ाइल संचालन, डेटाबेस और दूसरी कंपनियों के API जैसी एजेंट के बाहर की सुविधाएँ। Lecture 03 के फ़ंक्शन टूल उसी प्रक्रिया में थे; बाहरी टूल अलग प्रक्रिया या मशीन पर हो सकते हैं।
2. **MCP की भूमिका**: टूल देने वाले MCP सर्वर और इस्तेमाल करने वाले MCP क्लाइंट (एजेंट या एडिटर) के बीच साझा नियम। एक सर्वर किसी भी संगत क्लाइंट से समान तरीके से इस्तेमाल किया जा सकता है।
3. **सर्वर क्या देता है**: टूल के नाम, विवरण और तर्क का schema। मॉडल इन्हें पढ़कर कॉल चुनता है। Lecture 03 का docstring अब दूसरी प्रक्रिया से मिलता है।
4. **परिवहन**: stdio में क्लाइंट सर्वर को उपप्रक्रिया बनाकर शुरू करता है और मानक इनपुट/आउटपुट से बात करता है। Streamable HTTP में सर्वर URL पर प्रतीक्षा करता है और दूसरी मशीन से भी जुड़ सकते हैं।
5. **तैयार सर्वर**: फ़ाइल संचालन, वेब पृष्ठ लेना (`fetch`) और GitHub के सर्वर `mcpServers` सेटिंग फ़ाइल में जोड़कर इस्तेमाल कर सकते हैं। फ़ाइल लिखने और बाहर डेटा भेजने की अनुमति की ज़िम्मेदारी उपयोगकर्ता की है।
6. **नामस्थान और लागत**: अलग सर्वरों के टूल "सर्वरनाम_टूलनाम" से अलग पहचाने जाते हैं। अधिक टूल पर मॉडल को अधिक विवरण भेजना पड़ता है; इससे टूल चुनने की सटीकता और प्रति कॉल टोकन संख्या प्रभावित होती है।
7. **सुरक्षा**: MCP सर्वर मनचाहा कोड चला सकता है। अज्ञात स्रोत के सर्वर न जोड़ें। HTTP पर उपलब्ध कराएँ तो प्रमाणीकरण और पहुँच सीमा पर विचार करें (Codespaces port forwarding डिफ़ॉल्ट रूप से private है)।

## अभ्यास में क्या करेंगे

- Lecture 03 के शब्दावली टूल को MCP सर्वर पर देंगे और उसी एजेंट से MCP के माध्यम से इस्तेमाल करेंगे।
- एक टूल उपलब्ध कराएँगे।
- केवल सेटिंग फ़ाइल बदलकर तैयार `fetch` सर्वर जोड़ेंगे।
